# Governance

ReleaseFence uses a maintainer-led model during the 0.x phase. Akhilesh Gogikar is the initial maintainer and release steward.

Routine fixes are decided through review based on scope, evidence quality, determinism, safety, compatibility, and maintenance cost. Material changes—new data collection, network access, schema breaks, license changes, or expanded legal claims—require an explicit written decision and a documented migration path.

Contributors earn broader review responsibility through sustained, accurate contributions and constructive review. Commit access is never implied by contribution volume. Conflicts are resolved by narrowing to the documented scope and observable technical evidence; the maintainer makes the final decision when consensus is not reached.

Releases require passing CI, an updated changelog, provenance review, and a tagged version. Security fixes may use an abbreviated private review process followed by a public explanation that does not expose reporters.
